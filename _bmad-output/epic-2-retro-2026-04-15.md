## Outcome Summary

Epic 2 delivered the complete candidate data ingestion pipeline:

- **Ingestion paths (5):** initial migration, recruiter CSV, recruiter PDF, ATS (Ceipal), email submissions — all sharing the chunked RPC + fingerprint-gate + sync-run tracking pattern.
- **Identity & deduplication:** deterministic fingerprinting (email 95%, email+name 98%, phone 85%, skills 50–90%), auto-merge, manual review queue with side-by-side comparison, append-only dedup decision audit.
- **Enrichment:** role classification via hybrid heuristic + LLM path, availability state machine with 7-day staleness detection and bulk refresh operations.
- **Observability & control:** sync run tracking across all 5 jobs, drill-down error pages, global scheduler control plane with claim-based locking, admin dashboard for scheduler management.
- **Recruiter UX:** 15-field candidate search with cursor pagination, saved searches, daily digests, dashboard-wide UI standardization.

First real production workload succeeded: 6,512-row CSV → 6,150 imported, 232 rejected (191 identity, 41 format). Zero production incidents.

## What Went Well

### Pattern Reuse Across Ingestion Paths (Biggest Win)

- **Chunked RPC persistence (Story 2-1):** `process_import_chunk` RPC with 1000 rows/transaction became the shared primitive for CSV (2-2), PDF (2-2a), dedup batching (2-5), and role deduction backfill (2-5a).
- **Content fingerprint gate (Epic 1 Story 1.11):** Reused in all 5 ingestion paths. Story 2-3 caught the empty-string `ceipalId ?? ''` bug that would have silently duplicated all Ceipal rows — the gate's test coverage paid for itself immediately.
- **Sync-run tracking (Story 2-4b):** Null-safe `createSyncRun()` integrated into all 5 job classes without blocking ingestion. Fire-and-forget observability became a cross-epic pattern.
- **Hybrid heuristic + LLM (Story 2-5a):** Cheap heuristic for 10K-row CSV batches, LLM fallback for low-confidence enrichment. Balanced cost at 731K-candidate scale.
- **Append-only audit tables:** `candidate_submissions`, `candidate_availability_signals`, dedup decisions, `sync_runs`, `schedule_runs`, scheduler policy versions — same immutable-history pattern replicated across six surfaces.

### Adversarial Review Process Matured

- Stories 2-5a, 2-6, 2-7 all used Sonnet adversarial review as a mandatory gate.
- Story 2-7 ran **two** adversarial passes and fixed 22 findings (7 do-now + 15 patch) — established the template for control-plane-grade scrutiny.
- 2-4b review surfaced a missing `error_message` column, missing `ON DELETE SET NULL`, overly-broad DB grants, SavedSearchDigestJob counter gaps, and UTC timezone bugs — all caught pre-merge.
- Dev-standards discipline from Epic 1 (test-mode guards, `.error` checks on Supabase responses) held — no repeat of Epic 1's HIGH findings on these patterns.

### Production Pilot Success

- Story 2-2 shipped to production on 2026-03-31 and ingested 6,150 real candidates. Error breakdown (191 identity / 41 format) validated the validation gate design.
- `extra_attributes` JSONB guardrails (64 keys max, 16KB max) prevented schema bloat from recruiter-uploaded columns.
- Zero rollbacks, zero data loss, zero incidents.

### Scale-Ready Querying (Story 2-4)

- 8 partial indexes + relevance-ranking composite index sized for 1M+ rows.
- Cursor pagination with composite cursor encoding solved pagination drift on non-id sorts — reusable pattern for all future large-table UIs.
- Candidate list expanded from 3 filters to 15 without touching query performance.

### Control Plane Landed Before Dependencies Needed It

- Story 2-7 (scheduler core) and 2-7a (admin dashboard) shipped together. The policy-versioning design (schedule_definitions linked to versioned policies) unblocks cadence control for Epics 3–6 without app redeploys.
- `FOR UPDATE SKIP LOCKED` + outbox consumer pattern is now the standard for distributed job coordination.

## What Was Challenging

### Emergent Scope Growth (71%, Second Consecutive Epic)

- Planned: 7 stories. Shipped: 12. Additions were 2-2a, 2-4a, 2-4b, 2-5a, 2-7a.
- Unlike Epic 1, this epic had a formal sprint-change-proposal (2026-03-31), but it only captured the CSV production pivot — the other 4 additive stories grew without a proposal each.
- Every addition was justified (recruiter PDF feedback, UI consistency gap, observability gap, enrichment need, scheduler admin UX) — but the pattern of mid-epic growth is now a trend, not an anomaly.

### Fingerprinting and Identity Bugs Were Sneaky

- Story 2-3: empty-string nullish-coalesce (`ceipalId ?? ''`) would have silently duplicated every Ceipal row. Only caught in round 4 of review.
- Story 2-5: field merge conflicts on `extra_attributes` took multiple iterations to resolve.
- Deterministic identity matching proved more error-prone than expected — review passes averaged 4–7 per identity-sensitive story.

### External System Integration Friction

- Ceipal auth field misnamed (`email` vs `username`) — same class of field-naming bug that hit Story 1.11 in Epic 1. Not caught by types.
- Ceipal XML token response parsing required a dedicated parser.
- Default 30-day email window was too narrow for first-run backfill; extended to 3650 days.
- Lesson: every new external connector loses 2–3 review cycles to naming/format discovery. This is the cost of integration, not a process bug.

### Unplanned AI Cost Discovery

- Story 2-2a: ~4% of recruiter-uploaded PDFs were scanned images requiring Claude Vision OCR fallback at ~$0.015/page. Not budgeted in the original story estimate.
- No cost runaway (covered by existing AI cost dashboard from Story 1-9a), but the unit economics of resume ingestion shifted mid-story.

### Cross-Cutting Grants and RLS Hygiene

- Stories 2-1 and 2-4b both surfaced overly-broad role grants (anon role initially granted write access to ingestion tables). Same pattern of issue across two independent stories.
- Indicates a gap in the default migration template: new tables inherit permissive grants unless explicitly tightened.

### Large Story Files Hit Token Limits

- Stories 2-4, 2-5, 2-5a exceeded 10K tokens in their spec files. Signals that the planning phase is underestimating complexity for broad feature stories. Consider splitting or trimming future specs.

### Agents Repeat the Same Mistakes Across Stories (Vivek's top frustration)

- Architecture, design, and capabilities lessons from Epic 1 and earlier Epic 2 stories are not consistently applied by implementation agents on new stories.
- Same classes of review findings keep resurfacing: grant hygiene, error-path handling, field-naming mismatches on connector code, missing guards on test helpers.
- Documentation in `development-standards.md` and prior retros exists but isn't being reliably pulled into agent context at story-execution time. Convention-by-example is not enforcement.
- Cost to Vivek: every story required multiple rounds of code review to catch regressions of already-known patterns. This is the single biggest drag on velocity in the epic.

### Test Quality Is Shallow — Happy-Path Bias (Vivek)

- Tests pass but don't actually verify the functionality they claim to cover.
- Error scenarios, edge cases, boundary conditions, and failure modes are underspecified — reviewers have to hand-construct these cases during review instead of tests catching them pre-review.
- Test count (340+) is misleading: quantity went up but assertion density and negative-case coverage did not keep pace.
- Compounds the "agents repeating mistakes" problem — shallow tests don't catch regressions of known issues.

### External System Calls Are Not Being Optimized (Vivek)

- Every external-system boundary (Ceipal, email providers, Anthropic, Supabase RPCs) is expensive in $ and latency. Stories are not treating this as a design constraint.
- Missing optimizations observed: N+1 RPC patterns (caught late in 2-2a review), no systematic caching layer for external reads, no obvious batching-first discipline on new connectors, no rate-limit buffers surfaced in story planning.
- Cost-awareness infrastructure exists (AI cost dashboard from 1-9a) but is treated as a post-hoc observation tool rather than a design input.

## Key Lessons Learned

1. **Pattern dividends compound across epics.** The repository pattern (1-8), AI service (1-9), fingerprint gate (1-11), and sync-run tracking (2-4b) each accelerated every subsequent story that touched them. Epic 2 shipped 71% more scope than planned largely because the platform foundations from Epic 1 made the additions cheap.

2. **Mid-epic scope growth is now the baseline, not the exception.** Two consecutive epics at 71% growth is a signal, not noise. The planning process should either (a) plan for growth explicitly with buffer stories, or (b) enforce change proposals strictly. Pretending epics will land at their original scope wastes planning effort.

3. **Identity-sensitive code needs more review passes than other code.** Fingerprinting, deduplication, and upsert logic averaged 4–7 review rounds. Budget accordingly in story sizing — or invest in a reusable identity-matching test harness that surfaces these classes of bugs earlier.

4. **External connector integration has a fixed cost.** Every new connector (Ceipal, future Gmail/Outlook/etc.) burns 2–3 review cycles on field naming, auth format, and pagination discovery. Treat this as a known cost, not a surprise.

5. **DB permission hygiene should be a migration template concern, not a per-story concern.** The same overly-broad grants issue appeared in 2-1 and 2-4b. Fix it at the template level so it never appears in a review again.

6. **Adversarial review model selection matters.** Opus-builds / Sonnet-reviews split caught meaningful issues on 2-5a, 2-6, 2-7, 2-7a. Story 2-7 in particular (22 findings over 2 passes) would have been unsafe to ship without it given the control-plane blast radius.

7. **Fire-and-forget observability is safe to add late.** Story 2-4b shipped after 4 of the 5 jobs it tracks were already in production. Null-safe sync-run creation meant zero risk to existing flows. This pattern should be the default for any cross-cutting instrumentation.

8. **Production pilots surface cost assumptions that unit tests can't.** Story 2-2a's Vision OCR fallback cost was discovered only after real recruiter uploads. Schedule pilot runs explicitly for any AI-in-the-loop ingestion path.

9. **Retros and dev-standards don't enforce themselves.** The same review findings keep recurring because lessons live in markdown files that agents don't reliably consult at execution time. Pattern reuse needs an active feedback mechanism — checklists in story context, review gates keyed to past retro items, or agent-side retrieval of prior lessons before coding — not just documented rules.

10. **Test count is a vanity metric without assertion depth.** A story with 30 tests that only hit the happy path is weaker than one with 10 tests that exercise the error envelope. Reviews should grade tests on negative-case coverage, not count.

11. **External-system call economy is a design-time concern, not a review-time concern.** Batching, caching, and rate-limit buffers need to be in the story spec before code is written. Catching N+1 patterns in review round 4 is too late.
